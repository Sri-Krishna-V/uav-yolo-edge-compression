Result D, part one: the runtime moves latency more than precision does. The same YOLO11s at 640 takes 390 ms on ONNX Runtime FP32, 294 ms on OpenVINO FP32, 272 ms with ONNX Runtime INT8 and 172 ms on NCNN, whose Pi 5 default precision is FP16. NCNN is 2.27× faster than ONNX Runtime FP32 and keeps AP-small at 0.089 against 0.090; INT8 costs 14 % of AP-small (0.078). Across all checkpoints NCNN FP16 is 2.0 to 2.3× faster than ONNX Runtime FP32 and has 28 to 37 % less latency than ONNX Runtime INT8. Caveat: NCNN’s gain bundles the runtime and its FP16 arithmetic, which this design cannot separate; and the ONNX Runtime FP32 cell throttled, so its 390 ms may read a little high. Earlier Pi 5 work used NCNN at FP32 and one resolution [25]. OpenVINO’s ARM plugin compiles the INT8 model with no int8 layer, so the Pi 5 has no OpenVINO INT8 cell (#38).
